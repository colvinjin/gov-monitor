# 学大教育 · 大模型品牌可见度监测 Agent

监测「学大教育」在国内主流大模型回答中的**提及率、首位率、正面反馈程度**，并给出竞品声量份额（SOV）与内容优化靶子。

本质上是 GEO（生成式引擎优化）的度量层：过去看百度排名，现在要看**用户问 AI 时，模型会不会主动推荐学大、推荐在第几位、怎么评价**。

## 一、它做什么

```
问题集 × 模型 × 重复采样
        ↓  调用各家 OpenAI 兼容接口
     模型回答全文
        ↓  提及识别（带中文子串消歧）
        ↓  推荐清单排名解析
        ↓  情感裁判（LLM 判定 + 词典兜底）
   逐条记录 data/raw/YYYY-MM-DD.jsonl
        ↓  report.py 聚合
   日报 Markdown + 看板 web_data.json + 趋势归档
```

### 监测的模型

豆包（方舟）、通义千问、DeepSeek、智谱 GLM、Kimi、文心一言（千帆）、腾讯混元、讯飞星火、MiniMax、百川 —— 共 10 家，全部走 OpenAI 兼容的 `/chat/completions`。
**配了哪家的 Key 就监测哪家，其余自动跳过**；新增模型只需在 `config.py` 的 `PROVIDERS` 里加一行。

### 问题集（`questions.py`，共 35 题）

| 类型 | 数量 | 作用 |
| --- | --- | --- |
| `category` 品类推荐类 | 20 | 问题里**不出现任何品牌词**，算提及率 / 首位率 / 平均排名 |
| `brand` 品牌问询类 | 10 | 点名问学大，算正面反馈程度与风险舆情 |
| `compare` 竞品对比类 | 5 | 算 SOV 与对比语境下的优劣势归因 |

> 问题集是这套系统最重要的资产。覆盖了全国/城市（京沪广深蓉汉西）、学段（中考/高考/艺考）、需求（偏科/全日制/学情诊断）、政策（双减合规）等场景，可按业务重点继续扩充。

## 二、指标口径

口径不统一，不同人会算出完全不同的数，所以这里写死：

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| **提及率** | 提到学大的回答数 ÷ 品类问题回答总数 | **只用 `category` 类问题**。品牌问询类必然提及，计入会虚高 |
| **首位率（提及口径）** | 学大排第 1 的回答数 ÷ 提及学大的回答数 | 默认展示，回答"被提到时能不能当第一推荐" |
| **首位率（全量口径）** | 学大排第 1 的回答数 ÷ 品类问题回答总数 | 更严格，适合做长期 KPI |
| **平均排名** | 进入推荐清单时的名次均值 | 未进清单的不计入 |
| **正面率** | 情感判定为正面的回答数 ÷ 提及学大的回答数 | 覆盖全部问题类型 |
| **SOV 声量份额** | 学大被提及回答数 ÷ 各监测品牌被提及回答数之和 | 品类 + 对比类问题 |
| **可见度指数** | `100 × (0.45×提及率 + 0.30×排名得分 + 0.25×情感归一)` | 权重可在 `config.WEIGHTS` 调整 |

排名得分表（`config.RANK_SCORE`）：第 1 名 1.0、第 2 名 0.75、第 3 名 0.55、第 4 名 0.40、第 5 名 0.30、6 名以后 0.15、提及但未进清单 0.20、未提及 0。

### 两个容易踩的坑，已经处理

1. **「学大」是高频误匹配子串**——"教学大纲""数学大赛""学大概""同学大多""上学大约"都会被朴素正则命中，导致提及率虚高。`extractor.py` 用前后字符黑名单 + 强别名优先做消歧，`test_smoke.py` 里有 10 条针对性用例。竞品的"精锐""卓越""龙文""掌门"同理，要求上下文出现"教育/辅导/一对一"等限定词才算命中。
2. **排名不能只看谁先出现**——模型常给 `1. xxx\n   说明文字` 的清单，品牌可能出现在条目的说明行里。解析器按列表标记**切块**归属（支持 `1.`/`1、`/`（1）`/`一、`/`①`/`- `，并剥离 markdown 装饰），非清单式回答才退化为首次出现顺序。

## 三、使用

```bash
cd llm-brand-monitor
pip install -r requirements.txt
cp .env.example .env      # 填入至少一家模型的 API Key

python test_smoke.py                  # 离线自测（38 项，不需要 Key）
python monitor.py --dry-run           # 用 mock 回答跑通全流程，看看产出长什么样
python llm_client.py                  # 逐个模型做连通性测试

python monitor.py                     # 正式采集：全部已配置模型 × 全部问题
python report.py 2026-09-12           # 单独重算某天的报表
```

常用参数：

```bash
python monitor.py --providers doubao,qwen,deepseek   # 只跑指定模型
python monitor.py --types category                   # 只跑品类问题（省钱，指标最关键）
python monitor.py --repeats 5                        # 提高采样次数，降低随机性
python monitor.py --limit 5 --no-judge               # 快速冒烟，跳过 LLM 裁判
```

产出：

| 文件 | 内容 |
| --- | --- |
| `data/raw/YYYY-MM-DD.jsonl` | 每行一条回答，含**模型回答全文**，便于人工复核 |
| `data/daily/YYYY-MM-DD.json` | 当日聚合指标，同时作为趋势历史 |
| `reports/YYYY-MM-DD.md` | 人读日报（核心指标 / 分模型 / SOV / 口碑归因 / 优化靶子） |
| `web_data.json` | 看板数据 |

看板：

```bash
python3 -m http.server 8080
# 浏览器打开 http://localhost:8080/dashboard.html
```

（直接双击 html 会被浏览器 CORS 拦截，必须走 HTTP。）

### 定时运行

```cron
# 每天 08:30 采集并出报表
30 8 * * * cd /path/to/llm-brand-monitor && /usr/bin/python3 monitor.py >> data/cron.log 2>&1
```

## 四、结果怎么用

- **提及率低的问题**（日报"第五节 优化靶子"列出提及率为 0 的问题）→ 说明模型的知识/检索语料里学大在该场景缺位，是官网内容、百科、问答平台、媒体稿的投放靶子。
- **提及了但排名靠后** → 通常是品牌描述不够"可被引用"（缺少明确的城市覆盖、资质、师资结构等结构化事实），补足事实型内容比堆形容词有效。
- **负面率 / 风险表述** → 关注退费、资质、虚假宣传类表述在哪家模型出现，这类内容往往来自可被追溯的公开语料，需要单独处理。
- **SOV** → 与新东方、学而思等同业的相对位置，比绝对提及率更能反映竞争态势。

## 五、注意事项

1. **API 版和 App 版结果不一样**。豆包、元宝、Kimi 等 C 端 App 默认联网搜索，API 默认不联网，提及率通常更低。要对齐 C 端体验，可在 `config.PROVIDERS` 的 `extra_body` 里打开各家的联网开关（如通义的 `enable_search: true`），并**在报表里标注清楚是哪种模式**——两种模式的数据不能混着比。
2. **生成有随机性**。单次采样的提及率波动很大，`temperature` 保持 0.7（贴近真实用户场景），靠 `--repeats`（建议 ≥3）和逐日趋势来消噪，不要用单日单次结果下结论。
3. **模型版本会变**。各家模型静默升级会造成指标跳变，`data/daily` 里记录了当天用的 `model` 字段，解读趋势突变时先核对版本。
4. **结果仅代表模型的表述，不代表事实**。日报里的负面/风险表述是模型生成内容，需人工核实后再行动。
5. 本工具用于监测自有品牌在公开可得回答中的表现，请遵守各模型服务条款与调用频率限制。

## 六、文件结构

```
llm-brand-monitor/
├── config.py        品牌词表（含消歧规则）/ 模型清单 / 指标权重
├── questions.py     问题集（35 题，三类）
├── llm_client.py    统一 OpenAI 兼容客户端（重试、并发、mock）
├── extractor.py     提及识别 / 排名解析 / 情感兜底打分
├── judge.py         LLM 情感裁判（结构化 JSON，失败自动回落词典法）
├── monitor.py       采集主流程（Agent 入口）
├── report.py        指标聚合 / Markdown 日报 / 看板数据
├── dashboard.html   可视化看板（纯静态，无外部依赖）
└── test_smoke.py    离线自测 38 项
```
