# 学大教育 · 大模型品牌可见度监测 Agent

监测「学大教育」在国内主流大模型回答中的**提及率、首位率、正面反馈程度**，并给出竞品声量份额（SOV）与内容优化靶子。

本质上是 GEO（生成式引擎优化）的度量层：过去看百度排名，现在要看**用户问 AI 时，模型会不会主动推荐学大、推荐在第几位、怎么评价**。

## 一、先看这一条：真实用户走的是网页版和 App

网页版和 App **默认开联网检索**，API **默认不联网**。同一个问题，两者的提及率能差出一倍——
联网时模型会去检索"一对一辅导机构推荐"这类内容，谁在检索语料里谁就被提及；不联网时只靠模型自身知识。

所以本工具**以联网口径为基线**（`--mode web`，默认），并提供三条采集通道：

| 通道 | 贴近真实度 | 自动化 | 覆盖模型 | 用途 |
| --- | --- | --- | --- | --- |
| **接口** `monitor.py` | 中（能开检索的已开） | 全自动 | 10 家 | **高频日常监测**，每天跑 |
| **网页版** `browser_channel.py` | 高 | 半自动（登录一次） | 8 家网页版 | 周度校准，覆盖接口开不了检索的模型 |
| **App 人工** `import_manual.py` | 最高 | 人工问 + 一键导入 | 不限 | 月度基准，App 独有体验 |

三条通道产出**完全一致的记录结构**（`pipeline.py`），指标口径不会因采集方式漂移；
报表会自动按通道分列，**接口与网页版/App 的差值就是校准系数**——之后可以用接口做高频监测，定期用网页版/App 校准。

接口层能开联网检索的：通义千问、智谱 GLM、文心一言、腾讯混元、讯飞星火、百川；
豆包需要在方舟创建带联网插件的应用，把 Bot ID 填进 `ARK_BOT_ID`；
**DeepSeek / Kimi / MiniMax 接口层开不了**（Kimi 的联网是 builtin_function 工具回传，本工具未实现），这几家请走网页版或 App 通道。

> 各家的联网参数字段会随版本变动，所以工具不只记录"请求里开了检索"，还会扫描响应里有没有真的回传引用
> （`search_evidence` / `citations`），报表里能看到**联网实际生效比例**。跑 `python llm_client.py` 可以逐个模型验证。

## 二、它做什么

```
问题集 × 模型 × 重复采样
   ↓ 接口 / 网页版 / App人工  三条通道
模型回答全文
   ↓ 提及识别（带中文子串消歧）
   ↓ 推荐清单排名解析
   ↓ 情感裁判（LLM 判定 + 词典兜底）
data/raw/YYYY-MM-DD.jsonl
   ↓ report.py 聚合（按模式/通道分组）
日报 Markdown + 看板 + 14 天趋势
```

### 问题集（`questions.py`，共 35 题）

| 类型 | 数量 | 作用 |
| --- | --- | --- |
| `category` 品类推荐类 | 20 | 问题里**不出现任何品牌词**，算提及率 / 首位率 / 平均排名 |
| `brand` 品牌问询类 | 10 | 点名问学大，算正面反馈程度与风险舆情 |
| `compare` 竞品对比类 | 5 | 算 SOV 与对比语境下的优劣势归因 |

> 问题集是这套系统最重要的资产。覆盖全国/城市（京沪广深蓉汉西）、学段（中考/高考/艺考）、需求（偏科/全日制/学情诊断）、政策（双减合规）等场景，建议按业务重点继续改写。

## 三、指标口径

| 指标 | 公式 | 说明 |
| --- | --- | --- |
| **提及率** | 提到学大的回答数 ÷ 品类问题回答总数 | **只用 `category` 类问题**。品牌问询类必然提及，计入会虚高 |
| **首位率（提及口径）** | 学大排第 1 的回答数 ÷ 提及学大的回答数 | 默认展示，"被提到时能不能当第一推荐" |
| **首位率（全量口径）** | 学大排第 1 的回答数 ÷ 品类问题回答总数 | 更严格，适合做长期 KPI |
| **平均排名** | 进入推荐清单时的名次均值 | 未进清单的不计入 |
| **正面率** | 情感判定为正面的回答数 ÷ 提及学大的回答数 | 覆盖全部问题类型 |
| **SOV 声量份额** | 学大被提及回答数 ÷ 各监测品牌被提及回答数之和 | 品类 + 对比类问题 |
| **可见度指数** | `100 × (0.45×提及率 + 0.30×排名得分 + 0.25×情感归一)` | 权重在 `config.WEIGHTS` |

排名得分表（`config.RANK_SCORE`）：第 1 名 1.0、第 2 名 0.75、第 3 名 0.55、第 4 名 0.40、第 5 名 0.30、6 名以后 0.15、提及但未进清单 0.20、未提及 0。
一条都没被提及时情感项记 0 分（否则"没人提"会被当成"中性评价"白送分）。

**web 和 api 两种模式的数据分开统计、绝不混算**，报表里"联网 vs 不联网"一节给出差值。

### 两个会直接毁掉数据的坑，已经处理

1. **「学大」是高频误匹配子串**——"教学大纲""数学大赛""学大概""同学大多""上学大约"都会被朴素正则命中，提及率会虚高。`extractor.py` 用前后字符黑名单 + 强别名优先消歧，测试里有 10 条针对性用例。竞品的"精锐/卓越/龙文/掌门"同理要求上下文出现"教育/辅导/一对一"等限定词。
2. **排名不能只看谁先出现**——模型常给 `1. xxx\n   说明文字` 的清单，品牌可能出现在说明行里。解析器按列表标记**切块归属**（支持 `1.`/`1、`/`（1）`/`一、`/`①`/`- `，剥离 markdown 装饰），非清单式回答才退化为首次出现顺序。

## 四、使用

```bash
cd llm-brand-monitor
pip install -r requirements.txt
cp .env.example .env      # 填入至少一家模型的 API Key

python test_smoke.py                  # 离线自测 53 项，不需要 Key
python monitor.py --dry-run           # mock 数据跑通全流程，看产出长什么样
python llm_client.py                  # 逐个模型测连通性 + 联网是否真的生效
```

### 通道一：接口（每天跑）

```bash
python monitor.py                                    # web 模式（默认，开联网检索）
python monitor.py --mode api                         # 纯模型对照组
python monitor.py --providers qwen,glm,ernie         # 只跑能开检索的几家
python monitor.py --types category --repeats 5       # 只跑品类问题，提高采样
```

### 通道二：网页版（周度校准）

```bash
python browser_channel.py --list                     # 看已配置的 8 个网页版
python browser_channel.py --login doubao             # 打开浏览器手动登录一次
python browser_channel.py --probe doubao             # 打印候选选择器，校准 sites.json
python browser_channel.py --sites doubao,kimi --repeats 2
```

⚠️ `sites.json` 里的选择器是初始猜测（`verified: false`），各家前端改版频繁，**第一次用必须跑 `--probe` 校准**，校准完把 `verified` 改成 `true`。
登录态保存在 `.browser-profile/`（已加入 .gitignore，不会入库）。默认每题间隔 8 秒、非无头模式，节奏保守；不做任何验证码绕过。使用前请确认符合各平台服务条款。

### 通道三：App 人工（月度基准）

```bash
python import_manual.py --template --provider doubao_app --label 豆包App
# → 生成 data/manual/YYYY-MM-DD_doubao_app.md
# 在 App 里逐题提问，把回答原文粘贴到对应问题下方，然后：
python import_manual.py data/manual/YYYY-MM-DD_doubao_app.md
```

### 看板

```bash
python3 -m http.server 8080
# 打开 http://localhost:8080/dashboard.html
```

（直接双击 html 会被浏览器 CORS 拦截，必须走 HTTP。）

### 产出

| 文件 | 内容 |
| --- | --- |
| `data/raw/YYYY-MM-DD.jsonl` | 每行一条回答，含**回答全文**，便于人工复核 |
| `data/daily/YYYY-MM-DD.json` | 当日聚合指标，同时作为趋势历史 |
| `reports/YYYY-MM-DD.md` | 人读日报（核心指标 / 联网对照 / 分通道 / 分模型 / SOV / 口碑归因 / 优化靶子） |
| `web_data.json` | 看板数据 |

### 定时运行

```cron
# 每天 08:30 接口通道采集并出报表
30 8 * * * cd /path/to/llm-brand-monitor && /usr/bin/python3 monitor.py >> data/cron.log 2>&1
# 每周一 09:30 补一次不联网对照
30 9 * * 1 cd /path/to/llm-brand-monitor && /usr/bin/python3 monitor.py --mode api >> data/cron.log 2>&1
```

## 五、结果怎么用

- **提及率低的问题**（日报最后一节列出提及率为 0 的问题）→ 模型的检索语料里学大在该场景缺位，是官网内容、百科、问答平台、媒体稿的投放靶子。
- **联网 vs 不联网的差值** → 差值为正说明检索语料在帮学大（内容投放有效）；为负说明模型自身知识里学大更靠前、而检索把竞品带了上来，此时要优先做外部内容。
- **提及了但排名靠后** → 通常是品牌描述不够"可被引用"（缺少明确的城市覆盖、资质、师资结构等结构化事实），补足事实型内容比堆形容词有效。
- **负面率 / 风险表述** → 关注退费、资质、虚假宣传类表述在哪家模型出现，这类内容往往来自可追溯的公开语料，需单独处理。
- **SOV** → 与新东方、学而思等同业的相对位置，比绝对提及率更能反映竞争态势。

## 六、注意事项

1. **生成有随机性**。单次采样的提及率波动很大，`temperature` 保持 0.7（贴近真实用户场景），靠 `--repeats`（建议 ≥3）和逐日趋势消噪，不要用单日单次结果下结论。
2. **模型版本会变**。各家静默升级会造成指标跳变，`data/daily` 里记录了当天用的 `model` 字段，解读突变时先核对版本。
3. **结果仅代表模型的表述，不代表事实**。日报里的负面/风险表述是模型生成内容，需人工核实后再行动。
4. **联网参数字段会变**。`config.PROVIDERS` 里的 `search_body` 以各家最新文档为准，跑 `python llm_client.py` 看"联网"一列是否显示"已生效"。
5. 本工具用于监测自有品牌在公开可得回答中的表现，请遵守各模型服务条款与调用频率限制。

## 七、文件结构

```
llm-brand-monitor/
├── config.py           品牌词表（含消歧规则）/ 模型与联网配置 / 指标权重
├── questions.py        问题集（35 题，三类）
├── pipeline.py         三条通道共用的记录构建，保证口径一致
├── llm_client.py       统一 OpenAI 兼容客户端（重试、并发、联网证据、mock）
├── extractor.py        提及识别 / 排名解析 / 情感词典兜底
├── judge.py            LLM 情感裁判（结构化 JSON，失败回落词典法）
├── monitor.py          通道一：接口采集（Agent 主入口）
├── browser_channel.py  通道二：网页版采集（Playwright）
├── sites.json          网页版站点与选择器配置（需 --probe 校准）
├── import_manual.py    通道三：App 人工采集导入
├── report.py           指标聚合 / Markdown 日报 / 看板数据
├── dashboard.html      可视化看板（纯静态，无外部依赖）
├── test_smoke.py       离线自测 53 项
├── test_browser.py     浏览器驱动端到端测试（用本地模拟页，不碰真实站点）
└── testdata/           测试用的模拟聊天页
```
